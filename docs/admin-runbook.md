# 後台操作手冊

上架一件商品、換一張圖、讓網站更新 —— 這份文件回答這三件事，
以及出錯時該按哪裡。

---

## 一分鐘版本

1. 開 `https://<帳號>.github.io/<repo>/admin/`
2. 輸入密碼
3. 改東西、按「儲存」
4. 回清單按「發布」，等約 3 分鐘

儲存跟發布是兩件事。**儲存只寫進 Google Sheet，網站不會變**；
發布才會重新建置網站。這樣你可以連續改十件商品，最後發布一次。

---

## 資料在哪

商品資料在一份 Google 試算表裡，不在程式碼裡。分頁如下：

**有兩份試算表**，這是刻意的：

| 檔案 | 分頁 | 你會不會打開 |
|---|---|---|
| **Velora 商品資料** | `products`、`products_private`、`houses`、`categories`、`audit` | 常常 |
| **Velora 影像儲存** | `images` | 幾乎不會 |

分開的理由是效能：圖片以 base64 存放，一格四萬字元。Google Sheets 會把
每一格的內容都載進瀏覽器並渲染，二十幾列就足以讓整個檔案捲動卡頓 ——
而且會連帶拖慢你真正在編輯的 `products`。

代價：兩個 ID 要管（指令碼屬性 `SHEET_ID` 與 `IMAGES_SHEET_ID`），
**備份時兩份都要備**。

| 分頁 | 放什麼 | 建置流程讀得到 |
|---|---|---|
| `products` | 商品主表，只有可公開的欄位 | ✓ |
| `products_private` | FOB 成本、供應商備註、誘餌列 | ✗ |
| `images` | 圖片的位元組（base64，另一份檔案） | ✓ |
| `houses` / `categories` | 品牌、品類 | ✓ |
| `audit` | 操作紀錄 | ✗ |

**這份試算表永遠不可以設成「知道連結的任何人可以檢視」。**
分享權限是整份檔案層級的，`products_private` 在同一個檔案裡 ——
分享出去等於連成本一起分享。

後台可以直接編輯，也可以在試算表裡直接改。兩邊改的是同一份資料。
試算表適合大量修改（例如一次調十件商品的排序），後台適合單件編輯與上傳圖片。

## 成本為什麼永遠不會外流

不是靠「產生器記得別輸出」，是五層結構上的不可能：

1. **資料層隔離** —— `cost` 在 `products_private`。匯出端點的程式碼裡只有
   `getSheetByName('products')`，`products_private` 這個字串在那條路徑上不存在。
2. **欄位白名單** —— 產生器逐欄挑，絕不用 `{...row}` 展開。順帶擋掉
   「日後有人在 Sheet 加了一個叫 supplier_phone 的欄位」這種意外。
3. **輸出前斷言** —— 任何 key 命中 `cost|fob|unit_price|단가` 就中止建置。
   **這道斷言排在白名單之前**，所以它擋的是真正的威脅：端點開始回傳
   它不該回傳的東西。放在白名單後面的話它永遠不會觸發，等於不存在。
4. **誘餌字串** —— `products_private` 有一列 `id=__canary__`，成本值是一串隨機字，
   同時存在 GitHub Secret。CI 對整份輸出做逐字搜尋。這把「成本有沒有洩漏」
   從啟發式猜測變成確定性測試：只要洩漏路徑存在，誘餌必然一起洩漏。
5. **Sheet 端保護範圍** —— `products_private` 設了 Protected range，防手滑。

後台自己也不例外：`/admin/` 是公開網址，成本**不隨商品清單一起回傳**，
是登入後才能打的單筆查詢，而且每一次都會寫進 `audit` 分頁。

## 上架一件新商品

1. 側欄「新增商品」
2. **商品編號**：小寫英數與連字號，3–40 字，例如 `frg-ylang`。
   **建立後不可更改** —— 它是主鍵，改了等於換一件商品，
   舊的影像鍵與外部連結會全部指向錯的東西。
3. 索引碼、品類、品牌、HS 碼、產地
4. 三語文字：品名、標語、描述、材質、規格（香氛另有前中後調）
5. 圖片：點主圖區選檔案。壓縮在你的瀏覽器裡做，**原圖不會離開你的電腦**，
   EXIF（含 GPS 座標）會一併移除。
6. 上架設定、價格
7. 「儲存」→ 回清單 → 「發布」

### 三語一定要填嗎

中文一定要。英韓可以先空著 —— 前台缺譯會自動回退中文。
但正因為會自動回退，**你在前台看不出來哪裡缺**，所以清單頁會直接標「缺英文／缺韓文」。

### 圖片壓不下去怎麼辦

畫面會說「這張圖壓不到 34 KB 以內」。通常是整張都是細節的生活情境照。
兩個選擇：換一張去背或單品照，或勾「高畫質」放寬到 100 KB。
高畫質會佔三格儲存格，Sheet 會變大一點，其餘沒有差別。

## 發布

按「發布」之後：

| 狀態 | 意思 |
|---|---|
| 排隊中 / 發布中 | GitHub Actions 正在建置，約 3 分鐘 |
| 已上線 | 網站已更新 |
| 發布失敗 | 有一道稽核關卡擋下來了，見下 |
| 已被新的取代 | 你連按了兩次，舊的那次被取消，新的接手了 |

**發布會跑七道稽核關卡**，任何一道沒過就不會上線：

1. 後台字串不得出現在 `v1`／`v2`
2. 後台字串**必須**出現在 `admin`（沒有這道反向控制，一個空的 admin
   目錄會讓第 1 道無意義地通過）
3. 成本誘餌逐字搜尋
4. 試算表 ID 不得出現
5. 憑證形狀（`AIza…`、`ghp_`、私鑰、服務帳號信箱…）
6. 成本欄位形狀（第 3 道的補網，防誘餌列被誤刪）
7. `velora2/` 原始檔沒有被建置流程弄髒

失敗時到 GitHub 的 Actions 頁看是哪一關 —— 每一關的錯誤訊息都會說出原因。

> 🔴 `repository_dispatch` **只在預設分支上觸發**。目前工作分支是 `Velora2`，
> 合併回 `main` 之前按發布，GitHub 會回 204 成功但什麼都不會發生 ——
> 完全沒有錯誤訊號。

## 出事時

### 忘記密碼

沒有找回的方法（雜湊不可逆）。到 Apps Script 編輯器：

1. 專案設定 → 指令碼屬性 → 新增 `PW_NEW` = 新密碼
2. 執行 `setPassword`
3. 確認 `PW_NEW` 已自動消失

密碼要 12 字以上，不可含 `velora`、年份、鍵盤順序。中文一個字算一個。

### 被鎖在門外

連續輸錯會鎖一段時間。`/admin/` 是公開網址，Apps Script 拿不到來訪者 IP，
所以鎖定必然是全域的 —— **任何人都能故意輸錯把你自己鎖住**。
到編輯器執行 `unlock()`，30 秒解決。

第三次失敗時你會收到告警信。如果那封信不是你觸發的，代表有人在試。

### 密碼可能外洩

編輯器執行 `revokeAllTokens()`（讓所有已登入的 session 立刻失效），
然後照上面的步驟換密碼。

### 存了但網站沒變

先確認有沒有按「發布」。儲存只寫 Sheet。
如果按了發布也顯示已上線，但內容沒變 —— 檢查目前是不是在 `main` 分支。

### 後台打不開／一直轉圈

Apps Script 的部署可能是舊版。到編輯器：
部署 → **管理部署作業** → 選現有那筆 → 鉛筆 → 版本：**新版本** → 部署。

⚠️ 不要按「新增部署作業」，那會產生一個新的 `/exec` 網址，
已上線的前端仍指向舊的，症狀是「明明改了卻沒有效果」而且沒有任何錯誤訊息。

## 維護者的例行工作

| 什麼時候 | 做什麼 |
|---|---|
| 改了 `Code.gs` 或 `Api.gs` | 貼上覆蓋 → 重新部署（版本選「新版本」） |
| 改了 `Setup.gs` 的欄位定義 | 貼上覆蓋 → 執行對應的 patch 函式。**重跑 `setupSheets` 不會改既有表的標題列**，它刻意設計成不覆蓋資料 |
| 換過幾次商品圖之後 | `images` 分頁會累積沒人引用的舊圖列。目前沒有自動清理，一年清一次即可 |
| 部署前 | 編輯器執行 `selfTest`、`testPwRules`、`testValidate` |

### 可以在編輯器裡跑的函式

| 函式 | 做什麼 | 有沒有副作用 |
|---|---|---|
| `selfTest` | 驗雜湊、令牌、匯出邊界、KDF 成本 | 無 |
| `testPwRules` | 驗密碼規則真的會擋 | 無 |
| `testValidate` | 驗商品欄位驗證真的會擋 | 無 |
| `testWriteCycle` | 真的寫一件測試商品進去再刪掉 | **會寫入，跑完自動清除** |
| `checkAll` | 檢查 Sheet 結構 | 無 |
| `patchCategories` | 把 categories 分頁升到 11 欄 | 會改表 |
| `splitImagesBook` | 把 images 分頁搬到獨立的影像檔 | 會改表，有驗證後才刪 |
| `checkImages` | 看 Sheet 裡有幾張圖 | 無 |
| `seedImages` | 從線上站台把既有商品圖搬進 Sheet | 會寫入，可重複執行 |
| `testGithub` | 驗 GitHub 設定（唯讀，不觸發建置） | 無 |
| `setPassword` | 換密碼（讀 `PW_NEW` 屬性） | 會改，舊令牌全失效 |
| `unlock` | 解除鎖定 | 會改 |
| `revokeAllTokens` | 撤銷所有令牌 | 會改 |
| `initSecrets` | 第一次初始化 | **只能跑一次** |

## 絕對不要做的事

- **不要把密碼、`CI_EXPORT_KEY`、`COST_CANARY`、GitHub PAT 貼給任何人**，
  包含 AI 助理。貼了就當作已外洩，立刻重設。
- **不要把試算表設成公開可檢視。** 成本在同一個檔案裡。
- **不要按「新增部署作業」。** 用「管理部署作業 → 編輯 → 新版本」。
- **不要改已建立商品的編號。**
- **不要直接編輯 `src/data/*.generated.js`。** 下次建置就會被覆蓋，
  要改內容請改 Sheet。
